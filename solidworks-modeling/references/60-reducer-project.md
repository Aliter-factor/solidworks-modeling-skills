# 一级减速器全自动化建模 · 开发文档 v0.1

> 目的：把「北京建筑大学机电学院 solidworks 建模大赛」那套一级圆柱直齿轮减速器（35 件）
> 从**手工建模**升级为**脚本可复现**：零件 → 装配体 → 装配图，全程可校验。
> 本文是**方案与工具清单**，不是操作手册。看完要能拍板下面第 9 节那几个决策点。

---

## 1. 比赛要求原文（决定方案边界的三条）

图纸第 1 页写得很清楚，这三条直接约束我们的技术路线：

| 要求 | 对我们的约束 |
|---|---|
| 建立各零件的三维模型（35 种）；将零件组装为装配体；绘制减速器的装配图 | 交付物是**三层**，不是只有零件。装配层和图纸层必须一起设计，不能等零件做完再想 |
| 齿轮齿廓曲线采用**近似画法**（圆弧、样条曲线等） | 齿廓允许近似 → 现有 `gear_profile` 的 polyline/spline 两种模式够用，**再加一种"三段圆弧近似"**（传统制图法）更贴题意 |
| **标准件不允许用工具库插件创建** | 比赛明令禁止 Toolbox → 之前调研 Toolbox「规格取不出来」的结论不再是遗憾，而是**正好**。标准件全部走参数化模板 |

第三条顺带把上一轮遗留的问题彻底关掉了。

### 3.2 从基准数据里读出的 6 个结论

1. **齿廓算法被验证了**：齿轮齿顶圆实测 **113.976**，理论 `m(z₂+2) = 114`，差 0.024。
   我们自己 `gear` 模板实测 113.99 —— **两条路径撞同一个数**，说明齿廓构造方式与人工一致。
2. **齿轮轴 158.241 长、齿顶 Ø33.79~33.92**（理论 Ø34，偏小 0.1~0.2）——
   样条近似齿顶自然略低，属正常，**验收容差要按 ±0.5 设，不能卡 0.05**。
3. **箱体高度要留意**：箱座高 82.76 + 箱盖高 70.11 = **152.87**，
   而装配图标注总高 **172** —— 差的 19 mm 应该是**通气塞凸出部分**。
   建装配体时别把 172 当成"箱盖+箱座"的高度，否则会自己跟自己对不上。
4. **复杂度基准线**：36 件合计约 **932 个特征**，箱座 69 / 箱盖 54 / 轴承 37 是三个峰值。
   自动化要复现的是这个量级 —— 这也说明为什么必须用声明式计划而不是录宏。
5. **轴承是"单实体多特征"**（37 个特征、1 个实体）：内外圈+滚珠在零件里布尔成一体；
   真正带滚珠装配关系的那份在 `24-深沟球轴承-零部件及装配体\` 子目录里。
   **M3 装配层要决定用哪个**（单实体简单，但少一次装配练习；子装配体更像比赛要的"零件→装配"）。
6. **标准件与国标常规值有出入**：平垫圈 10 实测 **Ø22 × 1.5**、螺钉 M3 头部 **Ø6.0**，
   都与 GB/T97.1 / GB/T818 的常查值不完全一致。
   → M1 建"GB 标准值表"时**必须逐个核对**，并明确一口径：**跟图纸+参照件** 还是 **跟国标**。
   这个口径不先定，标准件会返工。（已列入第 9 节决策点）

## 4. 总体方案：三层 + 一验

```
          图纸 (8 页)                参照件 (35 件)
              │                            │
      ┌───────┴────────┐          ┌────────┴────────┐
      ▼                ▼          ▼                 ▼
  params.json    标准值表      reference.json   （人工复核）
  传动/箱体/零件    GB 手册查    包围盒/体积/质量
      │                            │
      └──────────┬─────────────────┘
                 ▼
        ┌────────────────┐
        │  计划生成器     │  每件一份 plan JSON（声明式，46+ op）
        └────────┬───────┘
                 ▼
   ┌─────────────┼─────────────┐
   ▼             ▼             ▼
 L1 零件层    L2 装配层     L3 图纸层
 sw_plan      asm_*        drw_*
   │             │             │
   └─────────────┼─────────────┘
                 ▼
        检证层（截图 + 读数 + 与参照件对账）
                 │
            不通过 → 变体轮询 → 仍不过 → 降级人工介入
```

### 4.1 为什么坚持"声明式计划"而不是录宏

上一轮已经验证过这条路的价值：宏是**命令式**的，改一个尺寸要重录；计划是**声明式**的，
一份 JSON 描述"要什么几何"，op 层负责"怎么落到 API"，于是：

- **可校验**：`--check` 离线跑，不启动 SolidWorks 就能发现参数缺失/前后矛盾（现有 1478 项断言）
- **可重放**：改中心距 → 全套零件跟着变（`{{ params.a }}` 引用）
- **可回退**：一个 op 可以带多套候选参数（变体轮询），失败自动换方案
- **可自证**：每步都能挂 `check_*`，建完立刻量

这个架构对 35 件零件的规模是**必要的**，不是过度设计 —— 手工 35 件 × 平均 15 个特征 ≈ 500 次操作。

### 4.2 三个层次的方案选择

#### 零件层：**方案 A（推荐）= 参数化声明式**
一份 `params.json` 存全部尺寸，35 份 plan 引用它。
备选：方案 B = 逐件硬编码尺寸（快但改不动）；方案 C = 手工。**建议 A。**

#### 装配层：**方案 B（推荐）= 自下而上 + 骨架定位**
- 方案 A 自上而下（布局草图/骨架驱动）：改中心距能带动整套，但 SW 的骨架建模 API 复杂、易断链
- **方案 B 自下而上**：零件全部建好 → 主装配体插入 → 用**坐标系对齐**先钉死两轴（中心距 70、中心高 80、
  同一剖分面），再逐件加配合。稳、可回退、每步可查
- 方案 C 手工装配：不采纳

**推荐 B**，但保留 A 的关键思想：把 70 / 80 这两个数放进 `params.json` 并写进装配计划，
使装配也能随参数重放。

#### 箱体层（唯一可能卡住的地方）：**三选一，建议 C**

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A 单草图实拉 | 把箱座当成"一个复杂外轮廓 + 拉伸 + 孔阵列 + 圆角" | 特征少 | 凸台/内腔/筋板共 20+ 个不同高度，单草图必然要大量"拉伸到面"，脆弱 |
| B 拆分体布尔 | 底板 + 4 箱壁 + 2 轴承座 + 筋板 各自拉伸，布尔并 | 每块简单、可单独调 | 布尔次数多，圆角在交界处易失败 |
| **C 脚本打底 + 人工收尾（推荐）** | 脚本生成"底板 + 箱壁 + 轴承座 + 全部孔位 + 剖分面"（约占 80% 工作量），**分箱面、拔模、成组圆角、窥视孔台阶**留给你在 SW 里点几下 | 规避最脆的几处 API，仍然省掉大部分重复劳动 | 不是 100% 无人化 |

理由：箱体失败点集中在**成组圆角**和**拔模**（API 对边的选取顺序极敏感，是工业界的通用痛点），
硬刚的收益远低于成本。剩下 33 件走全自动，整体自动化率仍能到 90% 以上。

### 4.3 ⭐ 尺寸录入方案（决定成败的一步）

**问题**：图纸尺寸抄错 = 白干，而且错在哪儿极难查。

**方案：单一数据源 + 交叉校核 + 逐件对账**

1. **单一数据源**：`assets/reducer/reducer.params.json`，分三块
   ```jsonc
   {
     "drive":  { "m": 2, "z1": 15, "z2": 55, "alpha": 20, "a": 70, "h": 80 },   // 传动
     "box":    { "L": 230, "W": 104, "H": 172, ... },                            // 箱体外形
     "parts":  { "shaft_out": {...}, "gear": {...}, "bearing": {...} }           // 逐件
   }
   ```
2. **交叉校核**（写进 `--check`，离线就能拦住大部分抄错）
   - `a == m*(z1+z2)/2`
   - `da1 == m*(z1+2)`、`da2 == m*(z2+2)`
   - `d1 + d2 == 2a`
   - 轴承内径 == 对应轴颈直径（6204→Ø20、6206→Ø30）
   - 端盖外径 > 轴承外径；挡油环内径 ≤ 轴颈
   - 箱体内腔 ≥ 齿顶圆 + 间隙；中心高 ≥ 大齿轮齿顶半径 + 油池深
3. **逐件对账**：建完一件立刻和 `reference.json` 比包围盒/体积，差超阈值就报错（见 6.1）

> 这一步是**先做**还是**边做边录**？建议先只录传动 + 箱体 + 齿轮/轴/轴承（约 8 件的关键件），
> 让 D0/D1 那 20 类小件在建模时随手录 —— 它们尺寸少、抄错代价低。

## 5. SolidWorks 特征 / 工具包装清单

用户要求："solidworks 所有的特征或工具的包装和工具制作"。

逐项标注 API / 参数要点 / 现状 / 优先级 / 坑）。

### 5.1 包装的工程约定（所有 op 统一遵守）

```python
OPS = {
  "extrude_boss": {
      "fn":    op_extrude_boss,
      "desc":  "拉伸凸台",
      "api":   ["IFeatureManager.FeatureExtrusion3"],
      "params": {
          "depth":    {"type": "mm",  "required": True,  "desc": "拉伸深度"},
          "end_cond": {"type": "enum","default": "swEndCondBlind"},
          "both":     {"type": "bool","default": False,  "desc": "双向"},
      },
      "verified": True,          # 真机跑通过
  },
}
```

六条铁律（都是从上一轮真机调试里换来的，不是抄文档）：

1. **入参一律 mm / deg**，内部乘 `MM` / `DEG` 再喂 API —— SolidWorks 内部是米和弧度
2. **不信返回值**：`Select4` / `SaveAs` / `InsertHelix` / `InsertCutSwept4` / `GetCoords` /
   `GetPartBox` 在晚期绑定下**都会说谎**。一律改用 *特征树前后 diff + `GetErrorCode` + 体积变化*
3. **每个建特征类 op 自带变体轮询**：主方案失败 → 换候选（方向/端条件/标记位）→ 全败才抛异常，
   并把"实际用了哪个方案"写进返回值和报告（键槽"只开一半"就是这么根治的）
4. **`GetTypeName2()` 回 `"ICE"` 不是错误**（Instant3D 的正常标记），真类型看 `GetTypeName()`
5. **一个 op 一个文件一行**：同一文件禁止并行 Edit（多个同发只有最后一个生效）
6. **改完 op 必须跑 `sw_ops.py --write-md` 重建操作文档 + `sw_selftest.py` 全量断言**

## 6. 验收标准（先定义"合格"，再动手）

### 6.1 零件层（逐件自动判）
| 项 | 判据 | 工具 |
|---|---|---|
| 有实体 | 实体数 ≥ 1 | `bodies` |
| 没坏特征 | 所有 `GetErrorCode() == 0` | 特征树遍历 |
| 形状对 | 包围盒**三个尺寸**（按集合比，**不计朝向**）与图纸/参照件差 ≤ **0.5 mm** | `check_bbox` / `reconcile` |
| 体积对 | 与参照件差 ≤ **2%**（复杂件如箱体放宽到 5%） | `check_mass` |
| 材料对 | 材料名与表1 一致 | 材料读取 |
| 肉眼对 | 三视图截图 | `sw_shot.py --grid` |

> ★ **为什么"形状对"不比朝向**（2026-10-02 真机修正）：参照件的旋转轴落在**不同的世界轴**
> 上（套筒 X / 调整环 Y / 密封圈 Z —— 人工建模各自随手选的平面）。坐标系朝向是**建模习惯**，
> 不是零件规格：同一个圆环转一下还是同一件东西。按轴逐一比会把"坐标系不同"误判成
> "零件不同"。故 `reconcile` 按**尺寸集合**比；朝向差异另作提示（见 `30-pitfalls.md` §71）。
> 本表里的"差 ≤ 0.5 mm"指**三个尺寸排序后**逐项比。

> **实作进度（2026-10-02 / v1.4.6）**：`parts` 现已登记 **35 件**（= `36 个参照 .SLDPRT
> − 1 个重复配置`；`14-弹簧垫圈 8` 有"伸缩/压缩"两态）。其中 **9 件**已有参数表驱动的
> 计划生成器并**逐件对账通过**：平键 10×8×22、轴（20-轴）、圆环族 5 件
> （套筒/调整环1/调整环2/密封圈/密封圈2）、闷盖族 2 件（端盖2/端盖4）。
> 进度表以 `sw_reducer.py --parts` 为准（**别在文档里手抄件数** —— 会漂移）。
>
> ★ **v1.4.6 修的前提性缺陷**：4 件端盖原先只登记在 `covers` 块（C6 校核的输入）里，
> `parts` 里没有 ⇒ **永远不会被建模**。补登记后 31 → 35，那道人眼对不上的差额就是它。
> 新增校核 **C11**：`covers` 与 `parts` 两张表 no/name/D/bearing 逐项一致。

### 6.2 装配层
| 项 | 判据 |
|---|---|
| 完整性 | 零部件数 = 35（轴承按子装配算 1，或展开算 5）✔ 与表1 逐项对 |
| 定位正确 | 实测两轴中心距 = 70 ± 0.1、中心高 = 80 ± 0.1（用质量属性/测量读） |
| 无干涉 | 干涉检查 ≤ 允许值（过盈配合、毛毡密封圈例外，需白名单） |
| 齿轮啮合 | 齿顶/齿根间隙 > 0；两齿轮分度圆相切（d₁/2 + d₂/2 = a） |

### 6.3 图纸层
| 项 | 判据 |
|---|---|
| 视图完整 | 主视（全剖）+ 俯视 + 左视 + 必要局部放大 |
| 明细表 | BOM 行数与表1 的 35 项一致，序号/名称/数量/材料/代号可对 |
| 标注 | 中心距 70±0.08、中心高 80±0.1、配合尺寸（Ø20h6/k6 等）齐 |
| 输出 | 导出 PDF 非空、能打开、图框正确 |

一条命令从零重放全流程；参照件基准表放在仓库里，任何人换台机器能复现判定。

## 9. 今晚要拍的 7 个决策点

1. **交付范围**：只做到零件（35 件）？还是必须到装配体？图纸要不要？（比赛要求是全套 → 默认全套）
2. **验收方式**：认不认"以你本地这 35 件为标准答案"？我建议认 —— 这是唯一能把"像"变成"是"的办法。
   如果老师要重新画一遍、不许用旧文件，那基准表只做校验、不做素材。
3. **箱体路线**：走 4.2 的 **C（脚本打底 + 你收尾）** 还是 **B（硬刚全自动）**？我建议 C。
4. **图框**：图纸层用学校发的图框，还是 GB 标准 A1/A2？前者要做自定义图纸格式（多一个 op）。
5. **范围控制**：要不要顺手把「装配图」的**零件图**也出了（M4 扩成 1 张装配图 + N 张零件图）？
   出零件图能让 BOM 对得更严，但工作量翻倍。
6. **标准件口径**（本轮扫描新发现，见 3.2-6）：平垫圈/螺钉的实测尺寸与国标常规值对不上。
   **以图纸+参照件为准**，还是**以 GB 手册为准**？口径不先定，标准件准返工。
7. **轴承形态**：用"单实体 37 特征"的零件（简单），还是用它子目录里那份**带滚珠的子装配体**？
   （比赛要考"零件→装配"，后者更贴题，但 M3 工作量 +1。）
