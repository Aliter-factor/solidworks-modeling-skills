# SolidWorks 自动建模

> **第一次接手：先跑 `python scripts/sw_doctor.py`**（离线体检，不需要 SolidWorks，一条命令给结论）。
> 装在哪、怎么验收、有哪些副作用，看 `INSTALL.md`。

## ⚠ 它会占用你**正在用的**那个 SolidWorks 会话（先看这条）

`SwSession.open()` **复用已运行的 SolidWorks 实例**，而所有操作都挂在 `app.ActiveDoc` 上。
⇒ 干活期间**别在 SolidWorks 里切换文档**：真机实测过读参照件读到一半，活动文档被换成
`d:\out\excavator.SLDPRT`（特征 28→49、体积 ×300），**而 `GetTitle` 还写着参照件名**。

两道守卫（2026-10-02 补）：
- **读**（`sw_profile` / `sw_refscan`）：读前读后各取一次指纹（`title/path/features/bodies/volume`），
  不一致就把这次结论**作废**（`_apply_drift` ⇒ `revolvable=False`）。
- **写**（`sw_plan --run` / `sw_probe`）：`new_part`/`open` 之后钉指纹（**只取 `title/path`** ——
  构建时特征/体积本来就在变），**每一步动手前**核对；漂了先按标题抢回，抢不回**中止**。
  否则 `extrude_boss` 会往**别人的模型**里加特征、`save_as` 会把**别人那份**存成我们的零件
  （它的三道验只看"存到哪了"，不看"存的是谁"）。
  逃生口：`--allow-doc-switch`（守卫**默认开**）。详见坑表 §93①。

## ⛔ 已封存的能力（先看这一节，别踩空）

**尺寸标注已主动封存（2026-10-02，用户决策）。** 计划里**不得**出现下列 op：

| 封存 op | 中文名 |
|---|---|
| `dim_auto` | 批量真尺寸标注 |
| `dimension` / `smart_dim` | 智能尺寸 |
| `fully_define` | 完全定义草图 |

**为什么封**：在**非单调回转型面**（端盖这类：法兰 → 台阶 → 轴承孔 → 毡圈槽 → 通孔，
轴向进进出出）上逐段标注时，SolidWorks 弹出**模态确认框**（过定义 / 冲突尺寸），
自动化当场挂死 —— 实测 `RPC_E_DISCONNECTED`（被调用的对象已与其客户端断开连接），
**并且型面已经被尺寸驱动改坏**（实体扭曲、读出 10.0075 这种歪值）。

**判据**（开发目录 `_diag/` 下的可复现实验，不进发行包）：只画
「中心线 + 折线(open) + `arc3p`」、**跳过 `dim_auto`**，直接 `revolve_boss` ⇒ **成功**。
⇒ 几何是对的，坏在标注这一步。

**现在怎么办**：

* 建模阶段**一条尺寸都不标**；几何正确性靠 `check_bbox` / `check_cyl_radius` / `check_mass`
  （透盖族的 `check_mass` 用 **Pappus 2π·r̄·A 从型面现算**，型面错一处立刻红）。
* 尺寸改由后续**「图纸绘制」**环节在**工程图**里标（不在建模草图里标）。
* `check_sketch_constraint` 保留，但 `expect_min_dims` 一律写 **0**（它降级为"记录约束状态"）。

**三道闸门**（不只写在文档里）：

1. `sw_ops.OpSpec.sealed` + `sw_ops.run_op` —— **执行期**，任何调用路径都拦。
2. `sw_spec` 的 **S3** —— **计划期**，计划里出现封存 op 即违规。
3. `assets/probes/_sealed/` —— 主题是标注的探针已退役（保留但默认不跑）。

**临时放行**（仅自检/诊断用）：step 上写 `"allow_sealed": true`，或设环境变量 `YOYO_ALLOW_SEALED=1`。
**重开条件**：找到不弹模态框的标注路径，并在真机上把全部零件重新跑绿。

## Overview

三层结构，各管一件事，互不越界：

| 层 | 文件 | 职责 | 是否碰 COM |
|---|---|---|---|
| 几何层 | `scripts/sw_gear.py` | 纯数学：渐开线齿轮、阶梯轴、键槽、六角螺栓、法兰、轴承 | 否 |
| 编排层 | `scripts/sw_plan.py` | 计划校验（状态机/参数/几何自检）+ 执行调度 | 只调度 |
| 接口层 | `scripts/sw_ops.py` + `sw_connect.py` | 把计划里的 op 翻译成确定的 SolidWorks API 调用序列 | 是 |

**核心思想**：AI 不直接写 COM 代码。AI 只写**计划**（声明式 JSON），计划先在本地离线校验一遍，通过了才执行。这样错误在"发指令"阶段就暴露，而不是等 SolidWorks 弹一堆对话框、建出一个歪零件再回头找原因。

## 开工前必做：环境体检

```bash
python scripts/sw_env.py            # 人读报告
python scripts/sw_env.py --json     # 机器读
```

体检项：SolidWorks 安装路径与版本、模板（`gb_part.prtdot` 等）、pywin32 是否可用、Python 位数与 SolidWorks 位数是否一致（**必须同为 64 位**，否则 COM 直接失败）。

若 pywin32 缺失（沙箱内 pip 常被拦），用清华源安装：

```bash
python -m pip install pywin32 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 标准工作流

```bash
# 1) 取骨架：先拿一份能跑的模板，再改参数，不要从零手写
python scripts/sw_plan.py --template gear > my_gear.json

# 2) 离线校验：这一步不碰 SolidWorks，几百毫秒出结果，必跑
python scripts/sw_plan.py --check my_gear.json

# 3) 执行（真正驱动 SolidWorks）
python scripts/sw_plan.py --run my_gear.json --report out/report.json

# 干跑：只走 API 调用链条不落盘，用于排查顺序问题
python scripts/sw_plan.py --dry-run my_gear.json
```

可用模板：`gear` / `shaft` / `bolt` / `flange` / `box` / `leadscrew`。
黄金样例在同名 `assets/plans/*.json`，也是回归测试的输入。

## 建完必须自查：截图 + 读数，不过就换方案

**建模不是"调通了 API 就算完"** —— 特征建出来了，也可能是坏的（键槽只啃半边、
拉伸方向反了、扫掠没出料）。所以每次真机执行后走固定两步：

```bash
# ① 截图看形状（默认 iso+front+right 三视图拼一张，便于对照图纸）
python scripts/sw_shot.py --doc D:\out\gear_v2.SLDPRT --out D:\out\shots --grid

# ② 读数看数值（特征树 / 错误码 / 草图图元 / 拉伸定义 / 包围盒 / 质量）
python scripts/sw_inspect.py --doc D:\out\gear_v2.SLDPRT --full --json D:\out\insp.json
```

| 判据 | 看哪里 | 不过怎么办 |
|---|---|---|
| 特征报错 | `sw_inspect` 的 `error_code`（`swFeatureError_e`） | 删掉重试 / 换 `variant` |
| 形状不对 | `sw_shot` 截图 | 换方向 / 换端条件 / 换基准面 |
| 尺寸不对 | `check_bbox` / `check_mass` | 改参数，别看拉伸"成功"就放过 |

接口层已经内置了**候选方案轮询**：`op_extrude_cut` / `op_extrude_boss` 会依次试
主方案 → 单向完全贯穿+反向 → 双向完全贯穿 → 两侧对称，用 `GetErrorCode` + 体积变化
筛掉坏的，选中的方案记进报告 `variant` 字段。**加新 op 时照这个模式写**：
先列候选调用序列，再逐个验证，"看返回值"永远不算验证。


## 核心概念

**状态机（顺序的守卫）**。每个 op 声明自己的前置状态与产生状态，编错顺序会在校验期报错而不是执行期崩：

```
new_part / open   →  doc_open
sketch_begin      →  sketch_open
sketch_end        →  sketch_closed
extrude/revolve/… →  has_feature
```

**单位**。SolidWorks 内部一律**米**，计划里一律**毫米/度**。转换只在接口层做（`mm()` / `deg()`）。角度用弧度。

**选择标记（selection mark）**。COM 里"选哪个对象"靠标记位区分：草图 `0`、阵列种子 `4`、方向参考 `1`、镜像面 `2`。选错标记 = 命令拿到错的对象。

**表达式**。计划参数可写算式引用前面步骤，例如 `"expression": "mn*(z+2)"`，由 `resolve()` 的 `AttrDict` 求值（支持 `params.mn` 形式），内置函数被屏蔽。

**校验器拦下来的错误**：op 不存在、必填参数缺失、`one_of` 互斥组（如圆必须给 `r` 或 `d`，不能都不给）、状态机顺序非法、齿轮根切、表达式求值失败、id 重复。

## 硬规则

1. **不猜 API 参数**。签名按这个顺序查：
   ① `sw_apisig.py --sig 接口.成员`（说明 / Remarks / 示例）；
   ② **`sw_apisig.py --tlb 接口.成员`**（`sldworks.tlb` 的**编译器级**参数表 ——
      参数个数、名字、类型、可选数，文档页抓不到时这是唯一可信来源）；
   ③ 枚举值查 `assets/sw_enums.json`（926 个枚举从本机类型库抽取）。
   猜错的参数**不会报错**，只会静默建出错的形状，或者悄悄建出一个空特征。
2. **"特征建出来了" ≠ 成功**。三级验收，一级都不能跳：
   ① 特征树新增（`_new_feature` 的 diff）；
   ② 返回的 `GetErrorCode` 必须是 0 —— **不是 0 就删掉重试下一个变体**，不要直接抛错终止；
   ③ **几何量对得上**：切除看体积减少、拉伸看包围盒、加筋看"轮廓围出的面积 × 厚度"。
   实测反例：`swStandardGBDrillSizes` 建出的孔"特征成功"但只啃掉 227 mm³ —— 孔几乎是空的。
3. **不跳过 `--check`**。执行前必须过校验器；跳过它省不了时间，只会在 SolidWorks 里翻车。
4. **`.swp` 宏不是源码**，是 p-code，解析不出来。遇到 `.swp` 请用户在 VBA 编辑器（Alt+F11）里导出 `.bas` 再翻译。

| op `dimension` 重写 | 按 `GetType()` 自动挑标注方式（圆→`AddDiameterDimension2`、直线→`AddDimension2`），并**自动把文字放到图元外面**；新增 `as` / `at` / `margin` / `anchor` 参数 |
| op `smart_dim` | 「智能尺寸」这个名字的同义词（**同一个 `OpSpec` 的第二个键**，不另抄一份定义） |
| op `screenshot` | 视口存盘（BMP+PNG），归 `verify` 类 —— **尺寸可见是纯视觉问题，数值断言抓不到** |
| 根因 | 旧实现把文字放在 `(0,0,0)`；而 `circle(cx=0, cy=0)` 的圆心正在原点 ⇒ **文字、原点标记、圆心点叠成一团灰影**（§56） |
| 完全定义 | `dimension(anchor=true)` → 选**圆心点** + `sgFIXED` ⇒ 状态 3 FullyConstrained，且直径**照样能驱动**（Ø30→Ø40 读回 40.0）。**锁整个圆会过约束并把尺寸锁死**（§57） |
| 死路一条 | `SelectByID2("Point1@Origin", …)` **五种变体全返回 False**，本机取不到草图原点实体，所以走不了「圆心+原点重合」（§58） |

其中 `diag_dim2` 被 **`EditRebuild3` 会退出活动草图** 骗了一轮（§59）。
验收：探针 `smart_dim`（20/20）+ `smart_dim_line`（17/17），全量 **31 探针 31 过**，

### 尺寸链标注（2026-09-25，v1.4.2）

用户口径：**「这是我们通常的标注习惯，而不是每个尺寸都标」**（附阶梯轴半剖面图纸截图：
`20` 台阶定位 / `10`+`15` 半径 / `50` 总长）。

`dim_auto(chain=auto)` 对**回转体半剖面**自动反推尺寸链，只标一套完整的：

| 尺寸 | 量什么（都给 `AddDimension2` 跨图元） | 文字位置 |
|---|---|---|
| 总长 | 左端面**竖线** ↔ 右端面**竖线** | 轮廓上方**最外圈** |
| 台阶定位 | 基准端**竖线** ↔ 台阶**竖线** | 轮廓上方**里圈**（平行、不重线） |
| 半径 → Ø | **轴线** ↔ 该段**母线** | 轮廓**右侧** |

- **判据 = 圆柱面**：`IFace2.GetSurface` + `CylinderParams[6]` 读出半径；
  母线（到轴距 ≈ 某圆柱面半径）参与定位+半径，端面（近似圆/样条）只参与总长。
  齿轮那种采样渐开线**没有圆柱面**，天然不被误标（圆探针 `dim_auto` 回归 23/23）。
- **为什么落点一定要分开**：`AddAlongXDimension`/`AddAlongYDimension` 是**单图元
  相对原点/轴**的距离。同一根母线既挂 X 又挂 Y ⇒ 后挂的被**静默拒绝**；
  更阴的是**重进过草图之后**（`revolve_boss` 后本 op 会自己退出再重进）
  它会把尺寸建到**邻居图元**上 —— 实测 seg3 的调用 `before=20.0`（那是 seg4 的值），
  `SetSystemValue3(15)` 静默失败、半径停在 20、`check_bbox` X=39.983。
  **返回值和 SetSystemValue3 都不报错，只能靠量几何发现。**
- 实测四条值 `D1=50 / D2=30 / D3=10 / D4=15`，每条 `before` = 目标值（不再串邻居）；
  截图复核 `30` 套在 `50` 里、`10`/`15` 在右侧 —— **与用户给的图纸习惯一致**。
- 验收：探针 `dim_auto_shaft`（27/27）+ `dim_auto`（23/23）。

### 环形件族：一个生成器覆盖 5 件（2026-10-02，v1.4.5）
